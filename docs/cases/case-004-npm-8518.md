# Case 004: npm exec bin name containing a dot on Windows

## Upstream context

- Upstream repository: https://github.com/npm/cli
- Public issue: https://github.com/npm/cli/issues/8518
- Upstream state observed on 2026-09-19: open.
- Public reproduction repository: https://github.com/molisani/npm-windows-bin-issue

The public reproduction package declares two bins that target the same script:
one ordinary name and one named `npm.windows-bin-issue`. The script only prints
`process.argv`.

## Local evaluation

- Host: Windows 10, PowerShell.
- Runtime: Node `v24.21.0`, npm `11.19.0`.
- Source: a shallow clone of the four-file public reproduction repository in
  an F-drive temporary directory.
- Commands: `npm exec --yes --package=. npm-windows-bin-issue` as the control,
  then the Issue-specific `npm exec --yes --package=. npm.windows-bin-issue`.

The control exited zero and printed the Node executable and script path. The
dotted bin exited zero but produced no stdout or stderr. CrossRepro captured the
dotted command, recorded exit code zero and empty streams, and found zero
redaction matches. It intentionally did **not** generate `repro.yml` because
v1 does not automatically infer a bug signature from a successful exit.
Evidence is retained under `.validation/oss-case-005-npm-8518/`.

## Result boundary

This is an **observed Windows functional difference**, with a same-package
control, rather than a v1 deterministic replay verdict. The v1 schema has no
`stdout.missing` or exact-output signature: it can express required output but
not the absence of expected output. This record is not an upstream issue
comment, PR, or maintainer feedback.

No CrossRepro core change was made from this case. It provides a concrete
candidate for a separately reviewed schema extension if missing-output verdicts
become in scope.
