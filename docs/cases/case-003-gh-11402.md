# Case 003: GitHub CLI browser path with spaces on Windows

## Upstream context

- Upstream repository: https://github.com/cli/cli
- Public issue: https://github.com/cli/cli/issues/11402
- Upstream state observed on 2026-09-19: open.
- Upstream issue version: `gh 2.74.2`; this local result is for current
  `gh 2.100.0 (2026-09-03)`.

The upstream issue reports that a configured browser path containing spaces is
corrupted before GitHub CLI executes it. The historical `gh 2.74.2` archive was
downloaded and checksum-verified, but it could not read this host's current
keyring authentication, so its `browse` operation did not reach browser
execution. The actual reproduction below uses the current authenticated CLI and
is not presented as a result for the old version.

## Local evaluation

- Host: Windows 10, PowerShell.
- Browser target: an inert temporary `.cmd` recorder in an F-drive directory
  named `browser path`; it writes received arguments and exits zero. It never
  opens a user browser.
- Command: `gh browse -R cli/cli` with `BROWSER` set to that recorder path.

The command returned exit code 1 with
`exec: "F:Codexcachecrossrepro-case003-ghbrowser": file does not exist`.
The recorder was not invoked, although its full path exists and contains the
required spaces. CrossRepro captured the command and replayed it on Windows as
`REPRODUCED`, matching `exit_code: 1`. Its sanitized stderr contains the same
corrupted path and the capture redaction report recorded zero matches and zero
high-risk matches. Local evidence is retained under
`.validation/oss-case-003-gh-11402/`.

## Result boundary

This is a **Windows-only local reproduction against gh 2.100.0**. It is not:

- a reproduction against the upstream issue's historical 2.74.2 binary;
- a three-platform result;
- an upstream issue comment, PR, or maintainer feedback.

No CrossRepro core change was required by this case. It validates a
privacy-safe, non-GUI way to capture a browser-launch path failure.
