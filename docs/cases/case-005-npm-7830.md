# Case 005: npm exec truncates a PowerShell multiline argument

## Upstream context

- Upstream repository: https://github.com/npm/cli
- Public issue: https://github.com/npm/cli/issues/7830
- Upstream state observed on 2026-09-19: open.
- Upstream report versions: npm 10.8.2 and Node 20.18.0 or 22.8.0; this local
  result is for npm 11.19.0 and Node 24.21.0.

The issue reports that a PowerShell argument containing a newline reaches a
direct Node script intact but loses its second line through npm exec.

## Local evaluation

- Host: Windows 10, PowerShell.
- Test package: temporary F-drive package with a single `assert-newline` bin.
  It is the Issue's minimal `process.argv` check with one added assertion:
  the final argument must equal `"a\\nb"`, otherwise it writes a safe mismatch
  message and exits 42.
- Control: the actual `node.exe` directly ran that script with `"a`nb"` and
  printed two lines with exit code zero.
- Target: `npm exec --yes --package=. assert-newline "a`nb"` received only
  `"a"`, emitted the assertion message, and exited 42.

CrossRepro captured that target command and replayed it on Windows as
`REPRODUCED`, matching `exit_code: 42`. The sanitized replay stderr records
`newline-argument-mismatch: expected="a\\nb" actual="a"`; the capture
redaction report recorded zero matches and zero high-risk matches. Local
evidence is retained under `.validation/oss-case-006-npm-7830/`.

## Result boundary

This is a **Windows-only local reproduction** against newer runtime versions
than those in the upstream report. It is not a three-platform result, upstream
issue comment, PR, or maintainer feedback. The assertion is a transparent
adaptation of the upstream minimal script so the real argument-loss condition
has a deterministic nonzero signature; it does not claim to be the original
command verbatim.

No CrossRepro core change was required by this case.
