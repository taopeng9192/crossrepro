# Case 002: uv `--overrides` path with spaces on Windows

## Upstream context

- Upstream repository: https://github.com/astral-sh/uv
- Public issue: https://github.com/astral-sh/uv/issues/21477
- Upstream state observed on 2026-09-18: open.
- Target release: `uv 0.12.9` for `x86_64-pc-windows-msvc`.

The upstream issue reports that `uv pip install --overrides` splits a quoted
requirements-file path at a space on Windows. This case evaluates the reported
minimal command without claiming an upstream diagnosis or maintainer agreement.

## Local evaluation

- Host: Windows 10, PowerShell.
- Target binary: the official `uv 0.12.9` Windows x64 Release archive, verified
  before extraction with SHA-256
  `ddbfcee1ac615a0499f6aa97b5ec8ebdf3ee4a7714a48055ec2ba0030e3cf810`.
- Test path: a temporary F-drive directory containing `uv test`, with an
  `override.txt` file containing `idna==3.10`.
- Sequence: `uv venv <space-path>`, then
  `uv pip install --python <space-path>\Scripts\python.exe --overrides
  <space-path>\override.txt --dry-run requests`.

Direct execution returned exit code 2 with
`error: File not found: F:\Codex\cache\crossrepro-case002-uv\uv`.
CrossRepro collected the same command using an explicit per-command
`-ExecutionPolicy Bypass` for the temporary script; it then replayed on Windows
as `REPRODUCED`, matching `exit_code: 2`. The sanitized replay stderr contains
the same truncated path, and the capture redaction report recorded zero matches
and zero high-risk matches. Local evidence is retained under
`.validation/oss-case-002-uv-21477-raw2/`.

## Result boundary

This is a **Windows-only local reproduction**. It is not yet:

- a three-platform result;
- an upstream issue comment, PR, or maintainer feedback;
- evidence that the current upstream tip still behaves the same as `uv 0.12.9`.

No CrossRepro core change was required by this case. The test does demonstrate
that a quoted path containing a space can remain visible in the sanitized,
deterministic reproduction report.
